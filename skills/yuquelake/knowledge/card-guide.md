## 第一部分：Card 能力目录

### 内容展示类

**`<card-codeblock>`** — 代码块
适合：需要复制的代码片段（命令行、脚本、配置文件、JSON 响应示例）。
不适合：行内代码（用标准 `<code>` 标签）。

**`<card-image>`** — 图片
适合：截图、界面说明、流程图图片、示意图。
不适合：矢量图或需要精细交互的图形（用 `<card-board>` 占位）。

**`<card-math>`** — 数学公式
适合：行内或行间数学公式，使用 LaTeX 语法。
不适合：普通文本中的数学符号（用 `<sup>`/`<sub>`）。

**`<card-diagram>`** — Mermaid/PlantUML 图表
适合：流程图、决策树、时序图、甘特图、UML 图。Mermaid 语法简单优先。
不适合：已有图片文件的流程图（直接用 `<card-image>`）。

### 结构组织类

**`<collapse>`** — 折叠面板
适合：分层信息组织——详细信息折叠不打扰主流程。可包含多个段落、表格、代码块。
不适合：核心内容（折叠后读者可能忽略）。

**`<columns>`** — 多栏布局
适合：左右分栏对比展示、图文并排、时间线与详情并排。
不适合：线性阅读为主的内容（分栏打断阅读流）。

**`<card-hr/>`** — 水平分割线
适合：分隔大章节、切换话题、视觉分隔。
不适合：小节之间（用标题层级区分即可）。

### 标记与提示类

**`<alert>`** — 提示框
适合：突出提示信息、警告、重要说明。有 info/warning/color1/color2 四种样式。
不适合：普通引用（用标准 `<blockquote>`）。

**`<card-label>`** — 标签/徽章
适合：标注状态、优先级、类型分类、注意事项标记。
不适合：段落正文中的强调（用 `<strong>`）。

**`<inline-label>`** — 行内标签
适合：在列表项内嵌入标签，标记必要条件、类型分类。
不适合：独立的标签标注（用 `<card-label>`）。

### 交互与数据类

**`<card-checkbox/>`** — 任务列表复选框
适合：创建任务清单、检查列表、待办事项。需放在 `<li>` 中使用。
不适合：纯展示性的列表（用 `<ul>`/`<ol>`）。

**`<card-datatable/>`** — 电子表格（占位符）
适合：需要动态排序、筛选、多视图切换的数据表格。
注意：无法通过伪标签从零创建，包含服务端数据。伪标签仅作占位符。

**`<card-board/>`** — 画板/架构图（占位符）
适合：复杂架构图、流程图、里程碑时间线。需要精细控制布局时使用。
注意：无法通过伪标签从零创建。伪标签仅作占位符。

### 辅助类

**`<card-file>`** — 附件
适合：提供 PDF、Excel、ZIP、TXT 等文件下载。

**`<card-date>`** — 日期
适合：标记日期、时间戳。

**`<card-calendar/>`** — 日历
适合：展示日历视图，适合会议安排、排期展示。

**`<card-yuque>`** — 语雀内容嵌入
适合：嵌入语雀知识库内的其他文档或数据表，带卡片预览。

## 第二部分：选择决策指南

选择伪标签遵循三级优先决策：**先判断信息类型 → 再匹配内容块模式 → 最后检查是否需要信息提取**。

### 第一级：判断信息类型

每个内容块必须先归为以下 6 种信息类型之一（定义见 [methodology.md](methodology.md)）：

| 信息类型 | 回答的问题 | 典型内容 |
|---------|----------|---------|
| Procedure（步骤） | 怎么做？ | 操作步骤、部署流程、检查清单 |
| Process（过程） | 发生了什么？ | 流程总览、状态流转、时间线 |
| Principle（原理） | 应该遵循什么？ | 规范、安全要求、注意事项 |
| Concept（概念） | 是什么？为什么？ | 术语定义、设计原则、选型理由 |
| Structure（结构） | 由什么组成？ | 架构说明、模块划分、参数清单 |
| Fact（事实） | 具体值是什么？ | 参数值、性能指标、错误码 |

判断信息类型后，进入第二级，按对应类型选择呈现形式。

### 第二级：按信息类型选择呈现形式

#### 内容块属于 Procedure（步骤）→

**内容块是"操作步骤"** →
**前置判断**：步骤中是否存在条件分支或多种路径？（如"如果是 A 方式→路径 1，如果是 B 方式→路径 2"）
- **是**：触发**复合模式**（流程总览图 + 详细步骤），见下方「复合模式」小节
- **否**：问步骤数量 > 3 且每步内容 > 2 段？
  - 是：用 `<collapse>` 折叠每个步骤
  - 否：直接用 `<ol>` 编号列表

**内容块是"任务清单"** →
用 `<card-checkbox/>` 放在 `<li>` 中

**内容块是"系统操作指引"** →
用 `<ol>` 编号步骤 + 每步配 `<card-image>` 截图

#### 内容块属于 Process（过程）→

**内容块是"流程总览"** →
问：需要展示判断分支？
- 是：用 `<card-diagram type="mermaid">` 流程图
- 否：用 `<table>` 步骤摘要表

**内容块是"甘特图/排期"** →
用 `<card-diagram type="mermaid">`（gantt 语法）

**内容块是"时间线"** →
用 `<table>`（时间 | 事件 | 说明）或 `<ol>` 有序列表

#### 内容块属于 Structure（结构）→

**内容块是"结构化清单"** →
问：需要排序？
- 是：用 `<ol>` 有序列表
- 否：用 `<table>` 表格（适合多列属性对照）或 `<ul>` 列表（适合单列项目）

**内容块是"参数对照表"** →
用 `<table>` 表格

**内容块是"架构图/部署拓扑"** →
用 `<card-diagram type="mermaid">`

**内容块是"数据模型/表结构"** →
用 `<table>` 表格；SQL 建表语句用 `<card-codeblock>`

#### 内容块属于 Fact（事实）→

**内容块是"错误码/状态码对照"** →
用 `<table>` 表格

**内容块是"性能指标/参数值"** →
用 `<table>` 表格（指标 | 值 | 单位 | 说明）

**内容块是"计算公式"** →
用 `<card-codeblock>` 代码块

#### 内容块属于 Concept（概念）→

**内容块是"术语定义"** →
用 `<table>` 表格（术语 | 含义）

**内容块是"设计原则/选型理由"** →
直接写正文段落；如需对比多个方案，用 `<table>`

**内容块是"概念解释"** →
直接写正文段落

#### 内容块属于 Principle（原理）→

**内容块是"提示信息"** →
问：有紧急程度区分？
- 是：用 `<alert type="warning">` 警告 / `<alert type="info">` 信息
- 否：用标准 `<blockquote>` 引用

**内容块是"安全警告/禁止操作"** →
用 `<alert type="warning">`

#### 通用模式（跨信息类型）→

**内容块是"代码"** →
问：是行内还是块级？
- 行内：用标准 `<code>` 标签
- 块级：用 `<card-codeblock mode="语言">`

**内容块是"图片"** →
用 `<card-image src="url">`，遵循下方"布局建议"

**内容块是"详细补充信息"** →
问：是否会让主流程分心？
- 是：用 `<collapse title="标题">` 折叠
- 否：直接写正文

**内容块是"文件下载"** →
用 `<card-file src="url" name="文件名">`

**内容块是"数学公式"** →
用 `<card-math code="LaTeX">`

**章节之间需要视觉分隔** →
用 `<card-hr/>`

### 复合模式：流程总览 + 详细步骤

当一个章节的内容**同时包含整体流程走向（含判断分支）和具体操作步骤**时，不是二选一，而是两层都要。这在 SOP、产品手册、教程等流程型文档中尤为常见。

**判断条件**（满足任一即触发复合模式）：
1. 章节内的步骤存在条件分叉——如"如果是 A 方式→路径 1，如果是 B 方式→路径 2"
2. 章节描述的是一个完整业务流程而非单一操作——如"缴费充值流程"而非"按下按钮"
3. 原文有多个 Step 但存在并行/分支关系而非纯线性

**复合模式的呈现结构**（按顺序）：
1. **第一层：流程总览图**（Process 类型）→ `<card-diagram type="mermaid">` 展示整体走向和判断分支，让读者一眼看到全貌
2. **第二层：详细操作步骤**（Procedure 类型）→ `<ol>` 编号列表或 `<collapse>` 折叠面板，展开每步具体操作
3. **第三层：系统操作截图**（如适用）→ 放在 `<collapse>` 折叠面板中

**不触发复合模式的情况**：
- 步骤是纯线性无分支（如"1.打开→2.输入→3.保存"）→ 直接走 Procedure 路径
- 内容是单一任务清单 → 直接用 checkbox
- 流程总览已有独立章节单独呈现 → 该章节不需要复合

## 第三部分：信息提取规则

原文中的信息常常散落在段落散文中，而非结构化呈现。在 Step 2（梳理）阶段，必须识别以下散乱信息模式并提取为结构化形式。此规则与信息类型判断配合使用——先判断信息类型，再按以下规则提取。

### 规则总表

| 散乱信息特征 | 提取为 | 提取方法 |
|---|---|---|
| 散乱参数/字段描述 | `<table>` 参数对照表 | 从段落中抽取字段名、类型、值、说明，每字段一行 |
| 散乱条件→结果描述 | `<table>` 条件→对策映射表 | 从段落中抽取条件、对应动作/结果，每条件一行 |
| 散乱对话/话术 | `<table>` 角色-话术表 或 结构化列表 | 按角色分组，话术原文逐字保留，不可改写 |
| 重复的相似条目描述 | `<table>` 对比表 | 抽取共同维度作为列，各条目作为行 |
| 时间线散落在段落中 | `<table>` 时间-事件表 或 `<ol>` 有序列表 | 按时间先后排序，抽取时间、事件、说明 |
| 散乱的关键值/指标 | `<table>` 指标表 | 抽取指标名、数值、单位、说明 |
| 散乱的角色职责描述 | `<table>` 职责分工表 | 抽取角色、职责、权限 |

### 提取决策树

面对一段散乱的段落内容，按以下顺序判断是否需要提取：

1. **段落中是否包含 3 个以上的命名实体（字段名、参数名、角色名、错误码等）？**
   - 是 → 进入第 2 步
   - 否 → 保留为正文段落

2. **这些实体之间是否存在结构化关系（对照、映射、对比、时序）？**
   - 是 → 提取为 `<table>` 表格
   - 否 → 保留为正文段落

3. **提取后是否丢失原文的语义完整性？**
   - 是 → 在表格前补充一段概括性文字，保留上下文
   - 否 → 直接用表格

### 提取示例

**散乱参数描述 → 参数对照表**：
原文：「接口超时时间默认是 3000 毫秒，最大可以设到 10000 毫秒。重试次数建议设为 3 次，不要超过 5 次。日志级别默认 info，生产环境建议 warning。」

提取为：
```
<table><tbody>
<tr><td>参数</td><td>默认值</td><td>建议值</td><td>说明</td></tr>
<tr><td>超时时间</td><td>3000ms</td><td>≤10000ms</td><td>接口请求超时阈值</td></tr>
<tr><td>重试次数</td><td>3</td><td>≤5</td><td>失败后重试次数</td></tr>
<tr><td>日志级别</td><td>info</td><td>warning（生产）</td><td>运行日志输出级别</td></tr>
</tbody></table>
```

**散乱条件→结果描述 → 条件映射表**：
原文：「如果用户未激活，需要先发送激活邮件。如果用户已激活但未验证手机号，跳转到手机验证页面。如果用户已激活且已验证手机号，直接进入首页。」

提取为：
```
<table><tbody>
<tr><td>条件</td><td>动作</td><td>说明</td></tr>
<tr><td>用户未激活</td><td>发送激活邮件</td><td>用户需点击邮件中的链接完成激活</td></tr>
<tr><td>已激活，未验证手机号</td><td>跳转手机验证页</td><td>验证后可进入系统</td></tr>
<tr><td>已激活，已验证手机号</td><td>直接进入首页</td><td>正常登录流程</td></tr>
</tbody></table>
```

**散乱对话/话术 → 话术表**：
原文：「客服应该说：您好，请问有什么可以帮您？如果客户表示要退款，回复：好的，我帮您查一下订单信息。如果客户情绪激动，回复：理解您的心情，我们会尽快处理。」

提取为：
```
<table><tbody>
<tr><td>场景</td><td>话术</td></tr>
<tr><td>开场</td><td>您好，请问有什么可以帮您？</td></tr>
<tr><td>客户要求退款</td><td>好的，我帮您查一下订单信息。</td></tr>
<tr><td>客户情绪激动</td><td>理解您的心情，我们会尽快处理。</td></tr>
</tbody></table>
```

### 提取的约束

1. **话术原文逐字保留**：涉及客服话术、操作口令时，提取后原文不可改写或意译
2. **话术呈现形式**：客服话术、操作口令、通知模板等需要复制的文本，使用 `<card-codeblock mode="plain">` 包裹，不用 `<blockquote>`。原因：codeblock 提供一键复制能力，话术是给客服直接使用的，必须可复制；blockquote 只是视觉引用，无法复制。`<blockquote>` 留给概念性引用（如"正如某某所说…"）。
3. **数值精度保留**：金额、参数值、计算公式提取后必须保持原始精度
4. **不强行提取**：如果段落只有 1-2 个实体，或实体间无结构化关系，保留为正文
5. **提取后补充上下文**：如果提取导致上下文丢失，在表格前加一句概括性文字

## 第四部分：布局建议

以下建议适用于所有文档类型，不涉及语法细节，只用文字描述"怎么放比较合理"。

### 图片布局

**通用规则**：
1. 每张图必须有图注，格式「图N：说明文字」，放在图片下方
2. 同一章节内的图片统一宽度，避免忽大忽小
3. 图片必须紧邻相关文字段落，禁止"孤儿图"（无文字说明的裸图）
4. 正文中必须引用图片（如"如下图所示"、"操作示例如下图"）
5. 图片上下各保留一个空行间距，确保呼吸感

**按数量布局**：
- **1-2 张图**：按顺序排列或左右分栏（`<columns>`）均可，根据内容自行判断
- **3 张及以上图**：统一布局——要么全部纵向堆叠统一宽度，要么全部放入 `<collapse>` 折叠面板避免占版面；选择一种，不混用

### 折叠面板使用

- 每个折叠面板只包含一个逻辑单元（一个步骤、一个端点、一个议题）
- 折叠面板标题必须概括内容，让读者不展开就知道大意
- 同一章节内折叠面板数量 > 5 时，考虑在章节开头添加摘要表
- 折叠面板可嵌套，但不超过 2 层——嵌套过深读者会迷路

### 提示框位置

- 警告类 `<alert type="warning">` 放在相关操作步骤之前，让读者先看到再执行
- 信息类 `<alert type="info">` 放在相关段落之后，作为补充说明
- 同一章节内提示框不超过 3 个——过多会削弱强调效果
- 不要连续放置两个提示框——合并为一个更长的提示

### 多栏布局时机

- 对比展示（两种方案左右对比）→ 适合多栏
- 图文并排（左图右文 或 左文右图）→ 适合多栏
- 线性阅读为主的内容 → 不适合多栏，用纵向堆叠
- 多栏列宽比例建议 40:60 或 50:50，避免极端比例

### 分割线使用

- 仅在大章节之间使用（如从"操作步骤"到"质量控制点"）
- 小节之间不用分割线——用标题层级区分
- 全文分割线数量不超过章节数——不是每个章节都要分割线

### 表格布局

- 表格列数 ≤ 5 列时直接展示
- 表格列数 > 5 列时，考虑拆分为多个小表或折叠非关键列
- 表格行数 > 10 行时，考虑用 `<collapse>` 折叠部分行或分页展示
- 相邻多个表格之间添加空行或简短过渡文字，避免"表格墙"
