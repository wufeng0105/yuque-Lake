# 规划流程指南

> 本文件描述在四步转换流程开始前和执行过程中，如何分析需求、规划处理路径、设置质量门。

## 一、Step 0：需求分析与处理规划

在四步流程开始前，先完成需求分析，输出一份处理规划表。

### 处理规划表

| 分析项 | 内容 |
|--------|------|
| 用户意图 | 转换为 Lake 格式 / 导入语雀知识库 / 批量迁移 |
| 输入格式 | Markdown / HTML / Lake / 纯文本 / 二进制（需提取） |
| 输入规模 | 单文件 / 多文件（N 个）/ 目录 |
| 文档类型 | 用户指定 / 自动检测 |
| 内容清点 | 图片×N 链接×N 代码块×N 表格×N 附件×N 数学公式×N 流程图×N 话术×N |
| 输出方式 | 单 .lake / 多 .lake / .lakebook 包 / 语雀 API 直传 |
| 文档标题 | 用户指定 / 从 H1 提取 / 从文件名提取 |

**内容清点**是后续所有质量门的校验基准——门 1 检查清洗后标记数 ≥ 清点数，门 2 检查每个元素在大纲中有锈点，门 4 检查输出中元素数 ≥ 清点数。清点时必须参考 [invariants.md](invariants.md) 中定义的不可变元素类型。

### 决策树

#### 规模分支
- 单文件 → 直接四步流程
- 多文件（≤5）→ 逐个处理，统一输出目录
- 多文件（>5）→ 批量自动化流水线

#### 文档类型分支
- 用户明确指定 → 直接读对应骨架
- 用户未指定 → 自动检测：
  - 含"步骤""操作""流程""SOP" → SOP
  - 含"接口""请求""响应""端点" → API 文档
  - 含"需求""功能""优先级""P0/P1" → PRD
  - 含"架构""设计""部署""模块" → 技术文档
  - 含"教程""学习""入门""实战" → 教程
  - 含"会议""纪要""议题""决议" → 会议记录
  - 含"项目计划""里程碑""排期""WBS" → 项目计划
  - 含"白皮书""方案论证""对比分析" → 白皮书
  - 含"手册""使用指南""FAQ""故障排查" → 产品手册
  - 含"设计规范""设计令牌""组件规范""无障碍" → 设计规范
  - 其他 → 自定义类型

#### 输出分支
- 单文件 → 输出 1 个 .lake
- 多文件 + 导入知识库 → 打包 .lakebook
- 多文件 + 语雀 API 可用 → API 直传

## 二、核心原则

**任何文档的流程第一步永远都是清洗格式，无一例外。**

- Markdown → 清洗 `#`、`**`、`*`、`>` 等标记
- HTML → 清洗 `<div>`、`<span>`、`<font>` 等标签
- **Lake → 先解析 `<card>` 标签提取内容，再清洗标签**（见 SKILL.md §1a-Lake）
- 纯文本 → 清洗空白、控制字符
- 二进制 → 先提取文本，再清洗

区别只在于清洗的对象不同，步骤 1 永远执行。Lake 格式输入的特殊性在于 `<card>` 标签同时是格式标记和内容载体——必须先解码提取内容再清洗，不能直接当 HTML 标签剥离。

## 三、步骤间质量门

### 门 0：输入验证（步骤 1 之前）
- [ ] 文件可读取，编码正确（UTF-8）
- [ ] 内容非空
- [ ] 文件格式已确认
- [ ] 内容清点已完成（图片/链接/代码块/表格/附件/公式/流程图/话术数量已记录）
- [ ] 已阅读 [invariants.md](invariants.md)

### 门 1：清洗验证（步骤 1 → 2 之间）
- [ ] 图片/链接/代码块/表格/附件/公式/流程图标记数 ≥ 门 0 清点数
- [ ] 表格行列数完整
- [ ] 内容顺序与原文一致
- [ ] 无残留格式标记
- [ ] 无控制字符
- [ ] **Lake 输入特有**：无残留 `<card>` 标签

### 门 2：梳理验证（步骤 2 → 3 之间）
- [ ] 文档类型已确定
- [ ] 已读取对应骨架参考文件
- [ ] 内容大纲已重组（纯文本，无标签）
- [ ] 每个内容块已归类（Procedure/Process/Principle/Concept/Structure/Fact）
- [ ] **不可变元素锈定**：门 0 清点中的每个元素在大纲中都有明确归属位置

### 门 3：伪代码验证（步骤 3 → 4 之间）
- [ ] 所有内容块都有对应伪标签或标准 HTML 标签
- [ ] 表格都有 `<colgroup>` 定义列宽
- [ ] 特殊字符已转义
- [ ] 文档标题已确定

### 门 4：输出验证（步骤 4 之后）
- [ ] `<!doctype lake>` 在文件开头
- [ ] `<title>` 和 4 个 `<meta>` 标签存在
- [ ] 无残留伪标签（搜索 `card-` 前缀 = 0）
- [ ] 所有 `<card>` 有 `name` 和 `value` 属性
- [ ] 所有 `value` 以 `data:` 开头
- [ ] **内容保全校验**：`python scripts/verify-content.py input output.lake` 返回 0（输出中不可变元素数 ≥ 门 0 清点数）

## 四、批量处理策略

### 自动化流水线
文件数 > 1 时，使用脚本流水线：
1. `md-to-lake.py`：Markdown → 伪标签 HTML（辅助完成步骤 1 清洗 + 步骤 3 格式转换，不做步骤 2 内容重组）
2. `lake-converter.py`：伪标签 HTML → .lake（步骤 4）

### 输出组织
- 统一放在 `lake-output/` 目录
- 文件名保持原名，扩展名改为 `.lake`

## 五、错误处理

| 错误场景 | 处理方式 |
|---------|---------|
| 文件编码错误 | 尝试 UTF-8 → GBK → Latin-1，记录实际编码 |
| 清洗后内容为空 | 停止处理，报告原文格式异常 |
| 文档类型无法判断 | 列出候选类型，请用户选择 |
| 转换脚本失败 | 保留伪标签 HTML，报告错误 |
| 输出验证不通过 | 列出具体失败项，建议修正 |

## 六、输出打包选项

| 选项 | 适用场景 | 输出 |
|------|---------|------|
| 单个 .lake | 单文档转换 | filename.lake |
| 多个 .lake | 批量转换 | lake-output/*.lake |
| .lakebook 包 | 导入语雀知识库 | knowledge-base.lakebook（tar） |
| 语雀 API 直传 | API 可用 | 直接创建文档，返回 URL |
