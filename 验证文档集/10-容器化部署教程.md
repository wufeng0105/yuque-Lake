## 一、环境准备

### 1.1 安装 Docker Engine 27.0+

Docker 27.0 版本带来了对 containerd 2.0 的原生支持和多架构构建增强。

**安装步骤（Ubuntu 22.04 LTS）**：

```bash
# 卸载旧版本
sudo apt-get remove docker docker-engine docker.io containerd runc

# 安装依赖
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg lsb-release

# 添加 Docker 官方 GPG 密钥
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 设置稳定版仓库
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装最新版本 Docker Engine
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 验证安装
sudo docker --version
# 应显示: Docker Engine - Community 27.0.x
```

**配置 Docker 以非 root 用户运行**（安全最佳实践）：

```bash
sudo usermod -aG docker $USER
newgrp docker
# 无需重启即可生效
```

### 1.2 部署 Kubernetes 1.30 集群

使用 kubeadm 部署最新稳定版 K8s 1.30。

**前置条件检查**：

| 检查项 | 要求 | 验证命令 |
|--------|------|---------|
| 操作系统 | Ubuntu 22.04+ | `cat /etc/os-release` |
| 内存 | ≥ 4GB | `free -h` |
| CPU | ≥ 2核 | `nproc` |
| 磁盘空间 | ≥ 50GB | `df -h /` |
| Swap | 已关闭 | `swapon --show` |
| 端口 | 6443, 2379-2380, 10250-10252 可用 | `netstat -tlnp` |

**安装 containerd**：

```bash
# 安装 containerd 2.0
sudo apt-get install containerd

# 生成默认配置
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml

# 修改 SystemdCgroup 设置
sudo sed -i 's/SystemdCgroup \= false/SystemdCgroup \= true/g' /etc/containerd/config.toml

# 重启 containerd
sudo systemctl restart containerd
sudo systemctl enable containerd
```

**安装 kubeadm, kubelet, kubectl**：

```bash
# 关闭 swap
sudo swapoff -a
sudo sed -i '/swap/s/^/#/' /etc/fstab

# 加载内核模块
sudo modprobe overlay
sudo modprobe br_netfilter

# 设置内核参数
cat <<EOF | sudo tee /etc/sysctl.d/kubernetes.conf
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward = 1
EOF
sudo sysctl --system

# 添加 Kubernetes 仓库
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

# 安装
sudo apt-get update
sudo apt-get install kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl
```

**初始化 Master 节点**：

```bash
sudo kubeadm init \
  --apiserver-advertise-address=10.0.0.10 \
  --pod-network-cidr=10.244.0.0/16 \
  --kubernetes-version=v1.30.0

# 配置 kubectl
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# 验证
kubectl get nodes
```

**加入 Worker 节点**：

```bash
# 在 Worker 节点执行（token 来自 init 输出）
sudo kubeadm join 10.0.0.10:6443 \
  --token abcdef.0123456789abcdef \
  --discovery-token-ca-cert-hash sha256:xxxxx
```

**安装网络插件（Calico）**：

```bash
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.0/manifests/calico.yaml
```

## 二、应用容器化

### 2.1 编写 Dockerfile

**Spring Boot 应用 Dockerfile 示例**：

```dockerfile
# 多阶段构建

# 阶段1: 构建
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn package -DskipTests

# 阶段2: 运行
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app

# 安装必要的工具
RUN apk add --no-cache curl tzdata && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone

# 复制构建产物
COPY --from=builder /app/target/*.jar app.jar

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD curl -f http://localhost:8080/actuator/health || exit 1

# 暴露端口
EXPOSE 8080

# JVM参数
ENV JAVA_OPTS="-Xms512m -Xmx512m -XX:+UseG1GC -XX:MaxGCPauseMillis=200"

# 启动命令
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

### 2.2 构建和推送镜像

```bash
# 构建镜像
docker build -t registry.example.com/order-service:v4.0.0 .

# 多架构构建（AMD64 + ARM64）
docker buildx build --platform linux/amd64,linux/arm64 \
  -t registry.example.com/order-service:v4.0.0 \
  --push .

# 登录私有仓库
docker login registry.example.com -u admin -p <password>

# 推送镜像
docker push registry.example.com/order-service:v4.0.0
```

### 2.3 镜像优化最佳实践

| 优化项 | 说明 | 效果 |
|--------|------|------|
| 多阶段构建 | 分离构建环境和运行环境 | 镜像减小60%+ |
| 使用Alpine基础镜像 | 替代完整OS镜像 | 镜像减小80% |
| 合并RUN指令 | 减少镜像层数 | 减少镜像大小 |
| .dockerignore | 排除不必要文件 | 加快构建速度 |
| 使用构建缓存 | 依赖先复制再复制源码 | 加快构建速度 |

## 三、Kubernetes 部署

### 3.1 编写 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
  namespace: production
  labels:
    app: order-service
    version: v4.0.0
spec:
  replicas: 3
  selector:
    matchLabels:
      app: order-service
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: order-service
        version: v4.0.0
    spec:
      containers:
      - name: order-service
        image: registry.example.com/order-service:v4.0.0
        ports:
        - containerPort: 8080
          name: http
        env:
        - name: SPRING_PROFILES_ACTIVE
          value: "prod"
        - name: JAVA_OPTS
          value: "-Xms512m -Xmx512m -XX:+UseG1GC"
        resources:
          requests:
            cpu: 500m
            memory: 768Mi
          limits:
            cpu: 1000m
            memory: 1536Mi
        livenessProbe:
          httpGet:
            path: /actuator/health/liveness
            port: 8080
          initialDelaySeconds: 60
          periodSeconds: 10
          failureThreshold: 3
        readinessProbe:
          httpGet:
            path: /actuator/health/readiness
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 5
          failureThreshold: 3
        lifecycle:
          preStop:
            exec:
              command: ["sh", "-c", "sleep 15"]
      terminationGracePeriodSeconds: 60
```

### 3.2 编写 Service

### 3.3 配置 HPA（水平自动扩缩容）

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: order-service-hpa
  namespace: production
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: order-service
  minReplicas: 3
  maxReplicas: 20
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
      - type: Percent
        value: 100
        periodSeconds: 60
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
      - type: Percent
        value: 50
        periodSeconds: 60
```

### 3.4 配置 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: order-service-ingress
  namespace: production
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/rate-limit: "100"
    nginx.ingress.kubernetes.io/rate-limit-window: "1m"
spec:
  tls:
  - hosts:
    - api.example.com
    secretName: tls-secret
  rules:
  - host: api.example.com
    http:
      paths:
      - path: /api/v1/orders
        pathType: Prefix
        backend:
          service:
            name: order-service
            port:
              number: 80
```

## 五、CI/CD 流水线

### 5.1 GitLab CI 配置

```yaml
stages:
  - build
  - test
  - quality
  - package
  - deploy

variables:
  IMAGE_NAME: registry.example.com/order-service
  IMAGE_TAG: ${CI_COMMIT_SHORT_SHA}

build:
  stage: build
  image: maven:3.9-eclipse-temurin-17
  script:
    - mvn compile -B
  artifacts:
    paths:
      - target/

unit-test:
  stage: test
  image: maven:3.9-eclipse-temurin-17
  script:
    - mvn test -B
  artifacts:
    reports:
      junit: target/surefire-reports/TEST-*.xml

quality:
  stage: quality
  image: maven:3.9-eclipse-temurin-17
  script:
    - mvn sonar:sonar -Dsonar.host.url=$SONAR_URL -Dsonar.login=$SONAR_TOKEN

package:
  stage: package
  image: docker:27.0
  services:
    - docker:27.0-dind
  script:
    - docker build -t $IMAGE_NAME:$IMAGE_TAG .
    - docker push $IMAGE_NAME:$IMAGE_TAG
  only:
    - main
    - develop

deploy-staging:
  stage: deploy
  image: bitnami/kubectl:1.30
  script:
    - kubectl set image deployment/order-service order-service=$IMAGE_NAME:$IMAGE_TAG -n staging
    - kubectl rollout status deployment/order-service -n staging
  only:
    - develop

deploy-production:
  stage: deploy
  image: bitnami/kubectl:1.30
  script:
    - kubectl set image deployment/order-service order-service=$IMAGE_NAME:$IMAGE_TAG -n production
    - kubectl rollout status deployment/order-service -n production
  only:
    - main
  when: manual
```

## 七、安全加固

### 7.1 容器安全

| 安全项 | 配置 | 说明 |
|--------|------|------|
| 非root用户运行 | `USER 1000:1000` | 避免root权限 |
| 只读文件系统 | `readOnlyRootFilesystem: true` | 防止恶意写入 |
| 禁用特权 | `privileged: false` | 最小权限原则 |
| 能力裁剪 | `drop: ["ALL"]` | 移除所有Linux能力 |
| 安全上下文 | `runAsNonRoot: true` | 强制非root |

### 7.2 Pod Security Standards

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
```

## 八、故障排查

### 8.1 常用排查命令

| 场景 | 命令 | 说明 |
|------|------|------|
| 查看Pod状态 | `kubectl get pods -n production` | 检查Pod运行状态 |
| 查看Pod详情 | `kubectl describe pod <pod-name> -n production` | 排查启动失败 |
| 查看容器日志 | `kubectl logs <pod-name> -n production` | 查看应用日志 |
| 查看上一容器日志 | `kubectl logs <pod-name> --previous -n production` | 崩溃前日志 |
| 进入容器 | `kubectl exec -it <pod-name> -- /bin/sh` | 容器内调试 |
| 查看事件 | `kubectl get events -n production --sort-by='.lastTimestamp'` | 排查调度问题 |
| 端口转发 | `kubectl port-forward <pod-name> 8080:8080` | 本地访问Pod |
| 查看资源使用 | `kubectl top pods -n production` | CPU/内存使用 |

### 8.2 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| ImagePullBackOff | 镜像不存在/无权限 | 检查镜像名和Secret |
| CrashLoopBackOff | 应用启动失败 | 查看日志，检查配置 |
| OOMKilled | 内存不足 | 调整resources.limits |
| Pending | 资源不足/调度失败 | 检查节点资源，查看events |
| 健康检查失败 | 应用未就绪 | 检查探针配置和应用状态 |
